# 产品部署与快速体验说明

本文面向现场评审和快速体验人员，目标是在本地启动后端、连接 Android 客户端，并用少量稳定场景验证推荐、加购、规格选择、购物车和图片导购流程。

## 1. 快速体验流程

1. 在电脑上启动后端服务，确认 `GET /health` 正常。
2. 连接 Android 客户端到后端：
   - 真机优先使用 `adb reverse`，客户端地址保持 `http://127.0.0.1:8000/`。
   - 模拟器使用 `http://10.0.2.2:8000/`。
   - 局域网体验使用电脑局域网 IP，并让后端监听 `0.0.0.0`。
3. 打开客户端进入聊天页，输入推荐或加购指令。
4. 观察推荐卡片、规格选择卡片、底部购物车数量和购物车页。
5. 演示前可清空固定 session 的购物车，保证状态干净。

## 2. 启动后端

后端 FastAPI 入口为 `backend/app/main.py`，默认端口 `8000`，API 前缀默认为 `/api`。本地商品数据来自 `ecommerce_agent_dataset`，当前数据集包含 151 个商品，涵盖美妆护肤、数码电子、服饰运动、食品生活四类。

### 2.1 配置运行模式

进入后端目录并准备依赖：

```powershell
cd backend
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

离线或快速演示可使用 mock LLM，启动更稳：

```powershell
$env:USE_MOCK_LLM="true"
$env:ENABLE_LOCAL_MODELS="false"
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

真实大模型体验使用本地密钥。请勿把个人密钥提交到仓库或展示给评审屏幕：

```powershell
$env:USE_MOCK_LLM="false"
$env:ENABLE_LOCAL_MODELS="true"
$env:DOUBAO_API_KEY="<填入本地密钥>"
$env:DOUBAO_BASE_URL="https://ark.cn-beijing.volces.com/api/v3/"
$env:DOUBAO_MODEL="ep-20260514111645-lmgt2"
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

当前仓库内已包含本地检索/重排模型目录，例如 `backend/models/bge-small-zh-v1.5`、`backend/models/text2vec-base-chinese`、`backend/models/bge-reranker-base`。如本地机器内存或启动时间受限，可临时关闭本地模型使用 mock 模式演示。

### 2.2 启动命令

本机体验：

```powershell
cd backend
.\.venv\Scripts\Activate.ps1
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

局域网真机体验：

```powershell
cd backend
.\.venv\Scripts\Activate.ps1
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### 2.3 检查后端状态

健康检查：

```powershell
curl.exe http://127.0.0.1:8000/health
```

SSE 聊天接口检查：

```powershell
curl.exe -N -X POST "http://127.0.0.1:8000/api/chat/stream" `
  -H "Content-Type: application/json" `
  -d '{"user_id":"judge_demo","session_id":"judge_demo_01","message":"推荐一款性价比高的手机"}'
```

正常情况下可看到 `progress`、`generation_started`、`recommendation_section_*`、`product_card` 或 `product_cards`、`response_completed`、`turn_result`、`done` 等事件。不同运行模式下事件数量可能略有差异。

常用接口：

- `GET /health`
- `POST /api/chat/stream`
- `POST /api/chat/stream/upload`
- `GET /api/products`
- `GET /api/products/{sku_id}`
- `GET /api/cart?session_id=<session_id>`
- `POST /api/cart/add`
- `POST /api/cart/remove`
- `POST /api/cart/update`
- `POST /api/cart/{session_id}/clear`

## 3. 连接 Android 客户端

Android 工程位于 `android/`。默认 `apiBaseUrl` 为 `http://127.0.0.1:8000/`，客户端会把聊天请求发到 `/api/chat/stream`，图片导购发到 `/api/chat/stream/upload`，购物车操作使用 `/api/cart/*`。

### 3.1 真机通过 adb reverse 连接

真机 USB 连接电脑后，后端可保持监听 `127.0.0.1:8000`，通过端口反向代理让手机访问电脑本机服务：

```powershell
adb devices
adb -s <设备序列号> reverse tcp:8000 tcp:8000
adb -s <设备序列号> reverse --list
```

构建客户端：

```powershell
cd android
.\gradlew.bat :app:assembleDebug -PapiBaseUrl=http://127.0.0.1:8000/
```

安装 APK：

```powershell
adb -s <设备序列号> install -r app\build\outputs\apk\debug\app-debug.apk
```

### 3.2 Android 模拟器连接

模拟器访问宿主机后端使用 `10.0.2.2`：

```powershell
cd android
.\gradlew.bat :app:assembleDebug -PapiBaseUrl=http://10.0.2.2:8000/
```

### 3.3 局域网连接

电脑和手机连接同一网络，后端使用：

```powershell
cd backend
.\.venv\Scripts\Activate.ps1
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Android 构建时填入电脑局域网 IP：

```powershell
cd android
.\gradlew.bat :app:assembleDebug -PapiBaseUrl=http://<电脑局域网IP>:8000/
```

### 3.4 启动客户端

可以用 Android Studio 打开 `android/` 目录运行，也可以安装命令行构建产物：

```powershell
adb -s <设备序列号> install -r app\build\outputs\apk\debug\app-debug.apk
```

当前仓库默认不提供预构建 APK；如 `android/app/build/outputs/apk/debug/app-debug.apk` 不存在，请先执行 `assembleDebug`。

## 4. 推荐体验场景

以下场景基于当前商品数据和测试用例整理，适合现场快速验证。

### 4.1 可信商品推荐

输入：

```text
推荐一款小棕瓶精华
```

预期：返回雅诗兰黛特润修护肌活精华露相关商品卡片，可看到商品名、价格、图片和推荐理由。

还可尝试：

```text
推荐防晒霜
推荐蓝牙耳机
推荐一款适合通勤的背包
```

### 4.2 多轮需求细化

输入：

```text
推荐10000元以内，拍照好的手机
```

继续输入：

```text
预算再低一点，优先续航和拍照
```

预期：系统结合上一轮手机需求继续筛选，不需要用户重复完整条件。

### 4.3 商品对比与指代

输入：

```text
推荐三款跑鞋
```

继续输入：

```text
第二款和第三款有什么区别
```

预期：系统能理解“第二款”“第三款”指代上一轮推荐结果，并给出对比。

### 4.4 加购与模拟下单

输入：

```text
推荐一款小棕瓶精华
```

继续输入：

```text
把第一款加入购物车
```

如果商品存在多个规格，预期只展示规格选择卡片，不展示“暂时没有找到完全符合条件的商品”这类推荐无结果提示。点击某个规格后，预期规格卡片折叠或替换为成功反馈，例如“已加入购物车：雅诗兰黛特润修护肌活精华露，30ml 经典装”，底部购物车数量同步更新。

也可直接指定规格：

```text
把第一款30ml加入购物车
```

预期：商品直接加入购物车。进入购物车页后可以看到对应规格和价格。

模拟下单：

```text
去结算
```

预期：系统返回模拟下单结果。Demo 阶段不会真实支付。

### 4.5 个性化与隐私模式

输入：

```text
关闭个性化推荐，不要根据历史推荐
```

继续输入：

```text
推荐一款清爽一点的防晒霜
```

再输入：

```text
开启隐私个性化，只用语义摘要，不要用原文历史
```

继续输入：

```text
再推荐一款清爽防晒
```

预期：系统能响应隐私偏好设置，并在后续推荐中使用对应记忆策略。

### 4.6 无精确匹配时的备选推荐

输入：

```text
推荐3000元以内拍照好的手机
```

预期：如果没有完全符合条件的商品，推荐流程可以展示放宽预算或备选商品提示。该提示只应出现在推荐/筛选类流程中，不应出现在加购、规格选择、购物车更新或结算流程中。

### 4.7 图片导购

客户端可上传图片并补充文字，例如：

```text
有没有类似这种款式，但价格低一点的背包
```

当前仓库内有可用于本地验证的图片文件，例如 `storage/test_pic` 目录下的本地手机照片文件；在当前 Windows 终端中该文件名可能显示为 `鎵嬫満鐓х墖.jpg`。商品数据集中也包含图片，例如：

- `ecommerce_agent_dataset/2_数码电子/images/p_digital_015_live.jpg`
- `ecommerce_agent_dataset/3_服饰运动/images/p_clothes_025_live.jpg`

真实视觉理解效果依赖 `VISION_MODEL` 或 `DOUBAO_VISION_MODEL` 等视觉模型配置。未配置视觉模型时，当前多模态链路会采用保守回退策略，测试时更依赖文本描述或文件名线索。

## 5. 五分钟演示脚本

1. 后端启动并执行健康检查：

```powershell
curl.exe http://127.0.0.1:8000/health
```

2. 打开 Android 客户端，输入：

```text
推荐10000元以内，拍照好的手机
```

3. 继续输入：

```text
把方案三加入购物车
```

4. 如果出现规格选择卡片，点击 `12GB+256GB · 标准版` 或任一可用规格。预期卡片变为成功反馈，底部购物车数量增加。

5. 进入购物车页，确认已加入对应商品和规格，例如 OPPO Find X9 Ultra 的 `12GB+256GB · 标准版`。

6. 回到聊天页输入：

```text
第二款和第三款哪个更适合拍照
```

7. 可选展示图片导购：上传背包或手机图片，并输入“有没有类似这种款式，但价格低一点的背包”。

## 6. 演示前状态初始化

固定 session 演示前可清空购物车：

```powershell
curl.exe -X POST "http://127.0.0.1:8000/api/cart/judge_demo_01/clear"
```

如果使用 Android 默认会话，客户端运行时会在 `android-demo-session` 后追加随机后缀。现场如需完全固定会话，建议用接口或调试日志确认当前 `session_id` 后再清理。

也可直接检查购物车：

```powershell
curl.exe "http://127.0.0.1:8000/api/cart?session_id=judge_demo_01"
```

## 7. 常见问题排查

后端无法访问：

- 确认后端命令运行在 `backend/` 目录。
- 确认端口是 `8000`，并先访问 `http://127.0.0.1:8000/health`。
- 局域网访问时确认后端监听 `0.0.0.0`，并检查电脑防火墙。

Android 真机连不上后端：

- USB 真机优先执行 `adb reverse tcp:8000 tcp:8000`。
- 客户端构建参数应为 `-PapiBaseUrl=http://127.0.0.1:8000/`。
- 如改用局域网 IP，需要重新构建或安装对应 APK。

规格选择后仍显示所有规格按钮：

- 正常预期是点击规格成功后，规格选择卡片折叠或替换为“已加入购物车：商品名，规格”。
- 如仍复现，请重点检查 Android 侧 `SpecSelectionUiModel`、`ChatViewModel`、`SpecSelectionCard` 和 `ChatScreen` 的完成态渲染逻辑。

加购流程后出现“暂时没有找到完全符合条件的商品”：

- 该提示只属于推荐/筛选无结果流程。
- 加购、规格选择、购物车更新、结算流程不应展示该提示；失败时应展示购物车操作失败原因。
- 如仍复现，请检查前端是否在 `cards` 为空时无条件补 no-result，以及当前 intent/flow 类型是否丢失。

图片导购效果不稳定：

- 确认已配置视觉模型相关环境变量。
- 未配置视觉模型时，可在文字中明确商品类型，例如“这是一款背包，帮我找价格低一点的类似款”。

## 8. 快速检查清单

- 后端 `GET /health` 返回正常。
- `/api/chat/stream` 能输出 SSE 事件。
- Android APK 已按当前连接方式设置 `apiBaseUrl`。
- 真机已执行 `adb reverse`，或局域网 IP 可以从手机访问。
- 推荐场景能展示商品卡片。
- 多规格商品加购时只展示规格选择卡片。
- 规格点击成功后显示成功反馈，不继续展示所有规格按钮。
- 加购、规格选择、购物车操作不出现推荐无结果提示。
- 底部购物车数量能更新。
- 购物车页能看到对应商品和规格。
- 推荐无精确匹配时仍能展示 no-result 或备选推荐提示。
- 演示前已清空或确认当前 session 的购物车状态。
