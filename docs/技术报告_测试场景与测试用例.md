# 电商智能导购 Agent 测试场景与测试用例

## 1. 文档目的

本文档为 `技术报告_0605.md` 第 7 章"测试与效果验证"的独立补充。它不是对现有 pytest 用例的简单整理，而是基于技术报告中明确宣称的系统能力，结合 `ecommerce_agent_dataset` 中 151 件真实商品数据和后端代码实际实现边界，重新设计的完整测试方案。

本文档面向以下使用场景：

- **答辩/演示**：从第 6 章选取核心展示场景，按推荐话术和操作顺序执行；
- **人工接口测试**：使用 curl、`http_stream_observer.py` 或 Postman 逐用例验证；
- **后续 pytest 编写**：每个用例的结构化断言可直接转化为 pytest 测试函数；
- **前端验收**：第 7.15 节提供 Android 端人工验收清单。

**重要声明**：本文档不修改任何业务代码、技术报告和现有测试代码。发现不一致时通过 `> 风险或不一致说明` 标注。

## 3. 测试环境

### 3.1 环境类型

| 环境标识 | 说明 | 适用场景 |
|---------|------|---------|
| MOCK | MockLLMClient，无需 Doubao API Key | 自动化接口测试、快速回归、CI |
| DOUBAO | 真实 Doubao 文本模型（需 API Key） | 语义理解质量、回复合理性验证 |
| VISION | 真实 Doubao 视觉模型（需 API Key + Vision Model） | 多模态测试 |
| LOCAL | 本地 BGE/text2vec/reranker 完整部署 | 检索排序精度验证 |
| NO_LOCAL | 禁用本地模型（`ENABLE_LOCAL_MODELS=false`） | 降级行为验证 |
| CURL | curl + `http_stream_observer.py` | 人工接口测试 |
| ANDROID | Android 真机或模拟器 | 前端交互验收 |

## 5. 测试设计原则

1. **从技术主张反推测试**：每个用例明确标注支撑哪项报告主张（C1-C15）
2. **使用真实商品数据**：所有商品引用必须附带 `product_id`/`sku_id`/数据文件路径
3. **结构化断言优先**：优先验证 intent/flow/parsed_query/retrieved_product_ids/cart_state/frontend_events 等结构化字段
4. **文本仅做语义检查**：自然语言回复只检查关键信息存在性、禁止内容和语义方向
5. **区分测试环境**：标注每个用例需要的 LLM 模式（MOCK/DOUBAO/VISION）
6. **区分测试类型**：自动化接口测试 / 后端组件测试 / 多轮 Agent 测试 / 故障注入 / 人工验收
7. **不虚构数据和结果**：所有预期结果基于代码实际行为推导
